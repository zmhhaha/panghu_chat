# 本地消息编辑器与 Copy 按钮重叠

记录日期：2026-09-17。

## 现象与原因

部署本地消息编辑器后，终端右下角原有的 Copy 按钮覆盖编辑器的 Terminal / Send 操作栏。

原注入脚本将 `LocalMessageComposer` 放在 `hostRef` 对应的 xterm 节点之后，
但仍位于 `termWrapRef` 对应的相对定位容器内部。Copy 按钮在该容器右下角绝对定位，
不占普通文档流空间，因此与新增编辑器的底部操作栏重叠。

## 修复方式

`scripts/apply-web-overlay.py` 为终端和编辑器增加共同的纵向布局容器：

```text
聊天主区域（横向排列）
  左侧列
    终端容器：xterm、Copy 按钮及原有终端浮层
    本地消息编辑器：文本框、Terminal / Send 操作栏
  右侧栏：模型、会话
```

编辑器与终端容器成为兄弟节点。Copy 按钮继续相对终端定位，不能覆盖编辑器。
注入脚本使用 `termWrapRef` 和桌面侧栏条件表达式作为边界，
以 `data-hermes-local-composer-column` 标记避免重复包裹，并移除旧位置的编辑器挂载。
上游结构不匹配时停止构建，需重新适配锚点。

`web-overlay/LocalMessageComposer.tsx` 同时调整：

- 编辑器不参与纵向压缩，宽度允许随父容器缩小。
- 文本框设置默认高度及最小、最大高度，避免无限拖高挤占终端。
- 操作栏允许换行，按钮组不压缩，状态文字可换行。

## 生效步骤与验证状态

在服务器同步代码后执行：

```bash
cd panghu_chat/hermes
bash build.sh
bash deploy.sh
```

必须重新构建镜像：Docker 构建时应用补丁并执行 `npm run build --workspace web`，
dashboard 实际提供的是编译后的 `web_dist`；仅修改源码或重启旧镜像不会生效。

记录时已完成代码修改，尚未构建、部署或验证本次布局修复。
部署后需检查桌面和窄屏中 Copy 与操作栏互不重叠，以及拖动文本框高度、
展开/收起侧栏、断线提示出现时的布局。布局检查无需发送消息调用模型。

## 交互可靠性补充

本地编辑器使用标签页内的 `sessionStorage`，按 profile 和恢复会话 ID 隔离草稿，
刷新可恢复，标签页关闭后不再永久累积草稿；新会话使用该 profile 的独立新会话草稿槽。
组件随 channel 切换重新挂载，避免将前一会话的编辑状态写入另一个会话。
终端状态为 `ended` 时清理对应持久化草稿，当前显示文本仍可复制。旧版 `localStorage`
草稿不再读取，也不自动删除，避免误删旧内容；如需清理，可在浏览器开发工具中删除
`hermes.local-composer.` 前缀的旧条目，不要删除认证或其他站点数据。

Send 按钮悬停提示 `Ctrl/Cmd+Enter` 提交、Enter 换行和可能打断当前任务。
因为目前没有可靠的 TUI busy/确认回执，每次提交要求明确确认，并提醒避开确认框和菜单。
这属于临时保护，不等于自动识别 TUI 状态或阻止终端侧竞态。

提交过滤粘贴边界序列和终端控制字符，保留普通文本的缩进、换行和 Tab。
bracketed paste 和回车仍间隔 50ms；定时器不代表服务端已接收，普通 PTY 输出也不能作为提交确认。
发送期间使用同步锁阻止连续提交，输入法组合和长按快捷键不触发发送。
断线、socket 更换或组件卸载取消待发回车；两步发送的异常均保留草稿，不自动重发。

写入 WebSocket 后显示 `Sent to terminal`，两秒后消失；错误提示保留。
成功发送也保留草稿，只有用户点击 Clear draft 或会话结束才清理保存内容，
避免在没有 TUI 确认的情况下丢失消息。重发前应核对终端，不能据此声称实现了消息去重或可靠送达。
